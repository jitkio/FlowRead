# FlowRead 阶段 3A：重排正文文字学习闭环设计与实现规范

## 一、概述与核心目标

阶段 3A 实现了 FlowRead 在无纸化流式重排视图下的**完整学习闭环**：
用户在流式重排正文中划选文字 -> 触发快捷工具栏 -> 可保存为高亮，或发起“解释/翻译/简化/Ask”等伴读操作 -> 生成伴读卡片在右侧跟随显示 -> 点击卡片“回到来源”平滑滚动定位并闪烁高亮 -> 重新打开文档或重启应用后高亮与卡片来源完整恢复。

本阶段完成了对重排文字学习链条的定点收尾修复，彻底解决了“普通卡片无高亮失去跟随”、“高亮覆盖层阻挡二次拖选”、“来源校验未真正接入跳转与恢复”、“历史解析版本绕过版本校验发起提问”以及“跳转平滑滚动用户接管中断”等关键接入缺口。

## 二、支持范围与限制边界

### 1. 支持范围
- **单块普通文字**：`paragraph`（正文段落）、`heading`（各级标题）内的文本划选。
- **跨行内样式节点**：同一块内跨越粗体 (`**text**`)、斜体 (`*text*`)、行内代码 (`` `code` ``)、链接 (`[text](url)`) 的连续文字选择。
- **元素级选区边界映射**：支持从 `Node.TEXT_NODE` 或 `Node.ELEMENT_NODE` + `childOffset` 映射选区（如 `selectNodeContents(p)` 正确计算字符起止偏移）。
- **公式与内联图片隔离**：位于行内公式 (`.katex`) 或内联图片前后的普通正文划选。

### 2. 明确拒绝并给出提示（不静默截断）
- **跨内容块选区**：起止节点跨越不同段落、标题或结构块时，明确拒绝并弹出轻提示：`"不支持跨内容块选择，请在单一段落或标题内选择文字"`。
- **穿过或进入数学公式**：选区落入 `.katex` / `.katex-display` 内部或穿过公式时，明确拒绝并提示：`"选区不能穿过或进入数学公式，请选择公式前后的普通文字"`。
- **跨越内联图片**：内联图片被统一封装为带有 `data-inline-image="true"` 的受控容器，选区跨越图片时明确拒绝：`"选区不能跨越或包含正文插图，请在插图前后选择文字"`。图片加载完成前后正文字符偏移保持恒定。
- **表格内划词**：暂不支持在复杂表格内划词标注，明确拒绝并提示：`"当前暂不支持在表格中划词标注"`。
- **源文档变更保护**：当源文档的 `revision` 与重排工作区的 `source_revision` 或锚点来源自身的 `sourceRevision` 不一致时，标记为只读模式，禁止新增高亮与卡片，并弹出提示：`"源文档自解析以来已发生变更，当前重排内容仅供只读参考，已禁止新增重排标记与卡片"`。

## 三、统一文字投影与数据契约

### 1. 数据结构 (`src/types/records.ts`)
```typescript
export interface ParsedTextSegment {
  blockId: string;        // 绑定的结构块 ID (如 "parsed_blk_0001")
  startOffset: number;    // 基于块纯净文字投影的 UTF-16 起始偏移 (0-indexed)
  endOffset: number;      // 投影终止偏移 (0-indexed)
  quote: string;          // 选区真实文本摘录
  prefix: string;         // 前导上下文 (最多 30 字符)
  suffix: string;         // 后缀上下文 (最多 30 字符)
  textHash: string;       // 确定性 FNV-1a 32 位十六进制文本哈希
}

export interface ParsedTextLocation {
  type: "parsed_text";
  schemaVersion: 1;
  parsedVersionId: string; // 绑定的内部解析工作区版本 ID
  sourceRevision: string;  // 对应源文件的版本修订哈希
  projectionVersion: 1;
  segments: ParsedTextSegment[];
}
```

### 2. 纯净文字投影与元素边界映射 (`src/utils/parsedTextAnchors.ts`)
KaTeX 与 ReactMarkdown 渲染时会生成复杂的内部 DOM 树。FlowRead 采用**无歧义正文投影模型**：
1. 遍历块内所有文本节点，跳过 KaTeX 隐藏层（`.katex-mathml`、`.katex-html annotation` 等）；
2. 将原子公式元素 (`.katex`) 与内联图片原子容器 (`[data-inline-image="true"]`) 分别投影为单个占位符 `\uFFFC`（长度固定为 1），确保公式和图片两端的正文字符偏移绝对恒定；
3. `resolveDOMBoundaryPoint` 支持文本节点与 Element + childOffset 双向映射；
4. 校验 UTF-16 代理对（Emoji 与扩展 Unicode 字符），禁止在半个代理对处断开；
5. 计算块正文全文字符串的 FNV-1a 32 位哈希 (`textHash`)，在卡片创建、高亮恢复与跳转定位时多层级核验。

## 四、几何定位与着色解耦模型

### 1. 来源几何与高亮着色严格分离
过去实现中因 `if (!entry.hasHighlight && activeAnchorId !== entry.anchorId) continue;`，导致只有已保存高亮或正处于激活态的来源才拥有 `data-anchor-id` DOM 节点。这使得“只创建过普通卡片、未另存高亮”的来源在文档重开（`activeAnchorId = null`）时失去跟随坐标。

修复后架构采用**分离的几何/着色模型**：
- **来源存在与可见性**：所有通过版本与哈希校验的当前解析版本锚点，无论是否有高亮颜色、是否激活，均在 `ParsedBlockHighlightLayer` 中建立几何外框容器并附加 `data-anchor-id`；
- **着色与强调样式**：
  - 只有真正持有高亮记录（`hasHighlight === true`）或处于选中激活态（`isActive === true`）时，才渲染可见色块；
  - 未保存高亮且非激活的普通卡片来源保持完全透明，不强行涂抹永久高亮，但在 DOM 中提供精确的几何范围，供 `checkVisibleAnchors` 与右侧跟随面板计算自然坐标；
- **鼠标事件穿透**：高亮层根节点与所有高亮色块设置 `pointer-events: none`，绝不拦截底层正文与链接的鼠标事件。

### 2. 字符级命中判断与点击/拖选精确区分
为了实现高亮区域既能被点击激活，又允许用户在已高亮文字内部再次划选提问：
- **正文容器事件接管**：在正文滚动容器上监听 `click` 事件；
- **字符级命中检测**：利用 `document.caretPositionFromPoint` 或 `document.caretRangeFromPoint` 取得点击处的实际文本节点与偏移量；
- **点击 vs 拖选区分**：
  - 若 `!window.getSelection()?.isCollapsed`，说明用户正在划词选择，绝不触发锚点点击；
  - 记录 `mouseDown` 与 `mouseUp` 坐标，位移超过 5px 视为拖拽选择，忽略点击；
  - 只有真正的单击且字符偏移命中已注册锚点的区间时，才激活对应卡片；
- 用户可从已高亮文字内部开始再次拖拽划选子串，创建重叠标记或发起深度追问。

## 五、统一全链条来源校验与安全防护

### 1. 统一校验入口 (`verifyParsedTextLocation`)
生产代码中所有涉及重排来源的环节（高亮恢复、来源几何注册、卡片跳转定位、从已有锚点发起提问），统一接入 `verifyParsedTextLocation`：
1. `schemaVersion === 1` 且 `projectionVersion === 1`；
2. `segments` 必须为且仅为一个有效片段；
3. `parsedVersionId` 与当前文档激活的工作区解析版本 ID 严格一致；
4. `sourceRevision` 与源文档及解析工作区修订哈希严格一致；
5. `blockId` 在当前重排正文中存在；
6. 偏移量为非负整数且 `startOffset < endOffset <= proj.text.length`；
7. 引用文本非空且长度与偏移量完全匹配；
8. 正文一致性哈希核对：`proj.textHash === seg.textHash`；
9. 实际切片正文核对：`proj.text.slice(startOffset, endOffset) === seg.quote`。

### 2. 内容篡改与版本不符防御
- **高亮拒绝绘制**：校验失败时，不渲染错误高亮，不污染正文排版；
- **跳转安全消费**：跳转目标若文本哈希或引用不符，立即消费该请求（调用 `onJumpComplete`），不滚动到猜测位置，并弹出轻提示：`"正文内容已变更，无法准确定位"`，防止死循环重试；
- **引用防篡改**：提问前若发现正文哈希不匹配，拒绝将错误上下文送入 AI；
- **容错防崩**：非法 JSON、缺失字段和异常块 ID 静默吞吐并提示，页面不崩溃。

## 六、App 操作代次与生命周期防竞态

### 1. 重排操作代次 (`reflowOpSeqRef`)
为了防止异步请求执行期间用户切书、切换解析版本或切回原版产生时序错乱，引入 `reflowOpSeqRef` 跟踪重排环境变化：
- 切换阅读视图（原版 <-> 重排）、打开新文档、切换解析工作区时，递增 `reflowOpSeqRef.current` 并废弃旧选区快照；
- 新增卡片与高亮时绑定发起时的 `boundReflowOpSeq`；
- 每次 await 之后（如保存锚点、保存卡片、读取图像等），均复核 `viewMode === "reflow"` 以及 `boundReflowOpSeq === reflowOpSeqRef.current`；
- 若操作已过期：
  - 尚未入队的任务立即终止，不再请求 AI 调度器；
  - 已创建的 queued 卡片调用 `apiUpdateCardStream(cardId, "", "interrupted")` 妥善结算，避免留下永远等待的任务。

### 2. 底部 Ask 来源校验
- 底部提问栏基于当前有效选区快照或当前激活重排锚点；
- 严格核对真实源修订版本，禁止将旧解析版本改包装为当前文档修订发起提问；
- 无有效重排来源时，输入框禁用并提示：`"请先在重排正文中选择一段文字，然后再发起提问... (按 / 聚焦，Ctrl+Enter 发送)"`；
- 移除“重排暂不支持选区提问，请切换至原版”的过时文案。

## 七、单次跳转调度与平滑滚动用户接管

### 1. 单次消费语义
- 每次跳转携带唯一 `requestId`，保证跳转请求单次分发与消费；
- 进入执行后立即调用 `onJumpComplete(reqId)` 消费请求，避免卡片保持选中状态导致视口锁死或重复触发定位。

### 2. 用户交互即时接管 (`handleUserTakeover`)
- 在平滑对齐滚动期间，在滚动容器与窗口上注册交互接管监听：
  - 鼠标滚轮 (`wheel`)；
  - 触摸滑动 (`touchmove`)；
  - 鼠标/触控板拖拽 (`pointerdown`)；
  - 键盘阅读导航键 (`PageUp`、`PageDown`、`Home`、`End`、`ArrowUp`、`ArrowDown`)；
- **输入框豁免**：输入框或文本域 (`input` / `textarea`) 内的键盘按键不被拦截，不影响用户正常打字提问；
- 一旦用户触发接管，立即注销监听、终止对齐状态并清理闪烁定时器；后续由于图片加载撑高内容或布局刷新，不再强制定位置。

## 九、Windows 桌面实机手工验收清单

在完成自动化测试后，推荐在 Windows 桌面真实客户端按照以下流程进行实机验收：

1. **普通卡片无高亮跟随排布**：
   - 打开已解析的 PDF 文档并进入“流式重排”；
   - 划选一段文字，点击“解释”生成卡片，**不点击保存高亮**；
   - 划选另一段文字，点击“翻译”生成第二张卡片，**同样不保存高亮**；
   - 点击第二张卡片激活它，观察右侧伴读栏：第一张卡片必须依然根据其在左侧正文中的位置正常排布，不消失；
   - 切换到其他文档再切回此文档（`activeAnchorId` 重置为 null），确认右侧伴读栏两张卡片均正常根据可见正文跟随出现，正文中无强加的永久高亮色块。

2. **高亮层鼠标穿透与文字内部再次拖选**：
   - 划选一段文字并保存为黄色高亮；
   - 将鼠标悬停在已高亮文字上方，光标应保持文本选择 `I-beam`；
   - 鼠标单击高亮文字，右侧伴读面板对应卡片应高亮激活；
   - 从已高亮文字的中间部分按住鼠标左键向后拖拽划选子串，确认能够正常选中文字并弹出快捷工具条；拖选结束绝不能误触发卡片切换。

3. **正文内容篡改/版本不匹配防御**：
   - 为某段正文创建卡片；
   - 模拟修改文档，使源文档修订版本递增；
   - 此时在只读重排视图下尝试点击底部提问栏发送问题，确认弹出 `"源文档自解析以来已发生变更，当前重排内容仅供只读参考，已禁止新增重排标记与卡片"`，未发出任何 AI 请求或生成空卡片。

4. **卡片定位回到原文与滚轮接管**：
   - 向下滚动数页，点击右侧某张卡片上的“回到原文位置”（⤾ 图标）；
   - 观察正文平滑滚动回到对应位置并伴有金色闪烁；
   - 再次尝试点击回到原文位置，在正文滚动途中立即拨动鼠标滚轮或按 `PageDown`，确认滚动动画被立即中断，用户可自由控制正文视口，无强行拉回或卡死现象；
   - 在底部提问栏内打字并按方向键移动光标，确认输入框按键不受影响。
