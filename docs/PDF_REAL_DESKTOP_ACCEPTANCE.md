## 三、真实联调暴露的明确阻断与精细收尾

本次联调严格遵循“只在暴露明确阻断时做最小修复，且严格限定修改范围”的原则，完成以下 4 项核心收尾：

### 1. 收紧公式兼容修复，保留原式保真度 (`src/components/ParsedBlock.tsx`)

- **问题背景**：真实解析结果中，公式 (5.53) 出现 `公式语法错误`（`Expected 'EOF', got '_' at position 67`）。经溯源，MinerU OCR 在生成 LaTeX 时将数学下标与条件描述词混入 `\text{...}`（如 `\text{for K > K_{crit}}`），KaTeX 在文本模式中遇到未定界下标 `_` 时编译抛错。前期宽泛的正则修复会将所有含 `_` 或 `^` 的 `\text` 内容直接剥离，不仅破坏了合法的文本下划线（如 `\text{signal\_name}`），而且可能破坏未知复杂嵌套结构。
- **收紧策略**：
  1. **首选原式**：组件优先尝试原样编译，仅当 KaTeX 原式抛错时，才触发容错重试；
  2. **转义符号保护**：引入 `hasUnescapedSubOrSuper`，使用零宽负向后顾断言 `/(?<!\\)[_^]/`，严格保留 `\_` 与 `\^` 等合法转义；
  3. **严格词法白名单**：仅识别经真实案例支持的条件引导词（`for|where|if|when|with|and|or|as|since|otherwise|case`），非白名单结构和未知文本一律不猜、不转，保留原样并显示局部兜底；
  4. **零破坏原始资产**：修复仅发生在前端渲染期，严格不改写内部工作区 `blocks.json` 或磁盘原始产物；
  5. **透明可交互提示**：修复成功后展示轻量提示微章（`已兼容显示`）及“查看原式 / 收起原式”折叠按钮，正常公式不展示任何多余提示；
  6. **保真性**：确保运算符、下标、条件判断和公式编号完整保留。
- **新增断言**：
  - 真实公式 (5.53) 兼容显示成功；
  - 混合包含 `\text{signal\_name}` 与错误条件的公式中，`signal\_name` 保持转义原样；
  - 未知表达式与不可靠嵌套结构不被转换；
  - 修复后可折叠查看原始源码；
  - 正常公式零干扰。

### 2. 差异化公式与编号布局，杜绝重叠与偏移 (`src/components/ParsedDocumentPreview.css`)

- **问题背景**：此前全局向所有独立公式容器添加固定 `padding-right: 5.5em`，导致大量无编号公式整体向左偏移无法居中；而面对长公式或窄窗口时，固定的右侧边距仍可能因容器收缩导致公式主体被编号覆盖。
- **精细化布局方案**：
  1. **容器区分**：根据渲染 HTML 中是否存在 `.katex-tag`，动态标记 `.has-tag` 与 `.no-tag`；
  2. **无编号公式 (`.no-tag`)**：左右边距完全归零（`padding: 0;`），数学公式严格居中排版；
  3. **有编号公式 (`.has-tag`)**：左右两端对称保留 `4.5em` 的专用安全通道，公式主体位于正中，编号绝对定位垂直居中右对齐，主体与编号物理分离互不侵犯；
  4. **长公式滚动**：公式主体超出时允许 `.parsed-formula-scroll` 容器内部横向平滑滚动，绝不覆盖右侧编号，也绝不撑破阅读器正文列；
  5. **段落行内公式隔离**：样式严格作用于块级独立公式（`.parsed-formula-container`），段落内部的行内公式 `$V = ...$` 保持自然流式混排，不受任何影响。

### 3. 限定下载直连回退适用范围与边界 (`src-tauri/src/parse_providers/`)

- **问题背景**：针对本地网络代理/分流导致的 `cdn-mineru.openxlab.org.cn` 下载失败，此前的回退逻辑采用字符串 `.contains()`，且缺乏对错误类型细分。
- **严格边界限定**：
  1. **精确 URL 校验**：使用 `url::Url` 解析器校验协议必须为 `https`，Host 必须严格等于 `cdn-mineru.openxlab.org.cn`（`is_eligible_mineru_cdn_url`），防范协议降级与路径/参数绕过；
  2. **结构化错误分类 (`DownloadError`)**：细分 `Network`, `HttpError`, `Oversized`, `LocalIo`, `EmptyContent`。仅在底层网络连接中断（`is_retryable_network()`）时触发**一次且仅一次**有限回退；文件超限、本地磁盘满/IO 错误、明确 HTTP 4xx/5xx 拒绝等绝不重复尝试；
  3. **保持端到端 TLS 校验**：回退客户端启用原生证书校验与主机名 SNI 校验，保持原域名与请求 URL，不降级 HTTP；
  4. **失败明确诊断**：回退客户端构建失败明确返回诊断错误，不静默换回原客户端；
  5. **架构局限性明示**：在代码与文档中详细注释“本策略属于针对特定 CDN 域名的临时地址覆盖（Temporary Address Override），当操作系统处于内核级 TUN 虚拟网卡强制劫持时，`no_proxy` 无法绕过内核分流”。

### 4. 纠正面板完成进度与时间文案 (`src/components/ParseJobsPanel.tsx`)

- **澄清页数**：终态成功任务明确显示“**解析已完成**”，并补充说明“（云端最后一次返回：9/22 页，服务商已确认全部处理完成）”，消除“为什么停在第 9 页”的误解；
- **澄清历时**：终态成功任务时间显示修正为“总历时 97小时43分（含排队与等待）”，诊断报告同步标注，避免误认为是云端单次解析耗时；
- **诊断常开**：非错误状态（包含运行中与成功任务）均可展开、复制完整诊断报告，诊断中的时间字段按“距最近更新”与“累计总历时”准确表达。
